# `tbdaq` manual

```text
tbdaq --machine PATH --acquisition PATH [--allow-local-output] [-v | -q]
      [run | show-config | endaq-info | endaq-stop]
```

`run` is the default. TestbenchDAQ deliberately has no combined `config.json`
or command-line setting overrides: a run is always defined by two complete
JSON files.

- **Machine file** (`testbenchdaq/machine/v1`) is an untracked, local host
  installation: machine identity, output root, installed Gator runtime, and
  enDAQ identity/mount/recovery settings.
- **Acquisition file** (`testbenchdaq/acquisition/v1`) is a portable
  measurement definition: name, scheduled windows, and explicit Gator/enDAQ
  choices. It can be generated by the Lager-Testbank TestDesigner.

Relative paths in the machine file resolve relative to that file.
`show-config` prints the resolved combined settings without hardware.
`endaq-info` describes an enDAQ enabled by the acquisition file.
`endaq-stop` stops/remounts that enDAQ after an interruption.

## Command options

| Option | Meaning |
| --- | --- |
| `--machine PATH` | Required local machine installation JSON. |
| `--acquisition PATH` | Required portable acquisition JSON. |
| `--allow-local-output` | Bypass the normal NFS/NFSv4 check once; the manifest records `local_override`. |
| `-v`, `--verbose` | Debug output, including native Gator messages; mutually exclusive with `-q`. |
| `-q`, `--quiet` | Less output: `-q` warnings/errors, `-qq` errors only; mutually exclusive with `-v`. |

## Acquisition-file behavior

`schedule` defines a diagnostic or repeated measurement. For repeated windows,
`run_period_s` is start-to-start and must accommodate recording duration,
startup/shutdown and device cleanup. `allow_partial` retains a session when an
enabled source cannot start, but marks it partial.

`gator` defines whether Gator is used plus its channel, sample rate, full scale
and threshold. Gator hardware installation remains in the machine file.

`endaq` defines whether enDAQ is used and a readable list of channel objects.
Each list item explicitly has `enabled: true` or `false`; only enabled channels
and their `sample_rate_hz` are enforced. Channel names, subchannel count and
rate limits are device-profile information that helps an operator make a valid
selection. Use `endaq-info` on the connected recorder before using a profile
for another model.

## Examples

```bash
# Validate the merged configuration
tbdaq --machine machine.json --acquisition acquisition.json show-config

# Start the measurement described by the two files
tbdaq --machine machine.json --acquisition acquisition.json

# Explicitly allow a temporary local setup run
tbdaq --machine machine.json --acquisition acquisition.json --allow-local-output

# Inspect or recover an enabled enDAQ
tbdaq --machine machine.json --acquisition acquisition.json endaq-info
tbdaq --machine machine.json --acquisition acquisition.json endaq-stop
```

| Status | Meaning |
| --- | --- |
| `0` | Successful session or inspection. |
| `1` | Partial, failed, aborted, interrupted, or runtime-failed session. |
| `2` | Invalid configuration. |
| `130` | Interrupted before manifest handling. |
